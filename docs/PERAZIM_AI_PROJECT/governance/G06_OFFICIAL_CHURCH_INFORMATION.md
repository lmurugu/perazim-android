## 1. Rule

The Guide may communicate church information **only** when it originates from an authorised church source and has passed the applicable approval and publication controls. It must never retrieve arbitrary database records and present them as official.

## 2. Sources by type

| Information | Authoritative source |
|---|---|
| Statement of faith | Approved, signed theological document (G01) |
| Official church history | Approved church document |
| Mission, vision, values | Approved church document |
| Leadership structure | Approved leadership register |
| Membership requirements | Signed church policy |
| Church constitution | Official governing document |
| Service times | Approved and currently published schedule |
| Upcoming events | Approved events records |
| Official contacts | Approved directory |
| Giving instructions | Approved financial communication |

## 3. Publication workflow for changing information

Frequently changing records use a controlled publication workflow. Each record carries:

- an **authorised publisher**;
- a **publication timestamp**;
- **source provenance** (which approved document or decision it came from);
- an **expiry date** where appropriate.

The signed knowledge package gives integrity and approval provenance. Controlled publication keeps the information current.

**Example:** an older signed document says services start at 9:00 AM. A newly approved schedule says 10:00 AM. The newer approved schedule governs. The Guide must not repeat the older time.

## 4. Conflicts

- A newer approved record overrides an older one.
- If the Guide finds an unresolved conflict between sources, it says so and points the member to the church office. It does not choose silently.
- Expired records are not presented as current.

## 5. Built-app baseline

The current app has a signed knowledge-package and governed-knowledge design in the project docs (documents 04, 17 and 19). Publication workflow fields (publisher, timestamp, provenance, expiry) are a **requirement to implement** in the knowledge store. This is an addition and does not contradict the built app.
