## Findings

### F-01 Accepting registration reveals whether a phone number is registered (decision D6)
- Severity: Medium. Category: OWASP API2 (user enumeration).
- Location: `server/src/routes/auth.js` register route, the 409 response.
- Description: sign-up says "An account with this phone number already exists".
- Impact: anyone can check whether a number belongs to a member. The register rate limits (per address and per phone) slow this down.
- Evidence: the 409 response text; rate limits added in commit `7728303`.
- Recommended fix: owner decision D6. Keep the message and record it as an accepted risk, or return a neutral answer that asks for verification.
- Notes: login enumeration is resolved (F-06).

### F-02 Refresh and access token lifetime is 30 days
- Severity: Medium. Category: OWASP API2.
- Location: `server/src/middleware/auth.js` `signToken` (`expiresIn: '30d'`).
- Description: a stolen token works for 30 days unless the member changes the PIN or deletes the account.
- Impact: longer exposure window for a stolen token.
- Recommended fix: 15-minute access tokens with rotating refresh tokens stored hashed (plan 3.5). Revocation by PIN change and erasure already exists.

### F-03 Relay daily quota is not atomic
- Severity: Medium. Category: race condition.
- Location: `relay/worker.js` (KV read then write around the quota, about lines 215 to 245). The code comments already say this.
- Impact: concurrent requests can exceed the daily quota.
- Recommended fix: a Durable Object counter (plan 3.7). Online AI is off in release builds, so exposure is currently limited to the test setup.

### F-04 Unbounded thread pool in the API client
- Severity: Low. Category: resource exhaustion.
- Location: `src/main/java/org/perazimchurch/app/data/remote/ApiClient.java:42` (`Executors.newCachedThreadPool`). Also `AsyncTask.THREAD_POOL_EXECUTOR` at `OfflineKnowledgeStore.java:975` and `AiBreakthroughGuideDialog.java:319`.
- Impact: a burst of requests can create many threads.
- Recommended fix: a bounded executor (plan 2.6).

### F-05 Caddy sends no security headers
- Severity: Medium. Category: OWASP API8.
- Location: `server/deploy/Caddyfile` (no `header` block). The API itself sends the headers now (helmet in `server/src/index.js`).
- Impact: HSTS, `nosniff` and framing rules are missing at the edge.
- Recommended fix: a Caddy `header` block with HSTS, `nosniff`, `frame-ancestors 'none'` and `Referrer-Policy`.

### F-06 Login no longer reveals whether a number is registered
- Status: Resolved on this branch (`7728303`), covered by `auth_pin_age_cutoff.test.js`.

### F-07 Room database included in cloud backup and device transfer
- Status: Resolved. `AndroidManifest.xml` sets `allowBackup="false"` (origin commit `faaabef`). Remaining note: `data_extraction_rules.xml` lists only session preference files; with backup disabled this is redundant but harmless.

### F-08 Sign-in PIN too weak (4 digits)
- Status: Resolved for new PINs (6 to 12 digits, bcrypt cost 12, `commit 58db048`). Existing short PINs still sign in and are offered an upgrade (`7728303`).

### F-09 Sync writes accepted from unauthenticated clients
- Status: Resolved. Origin fix S1 (`a03c9dd`) requires an authenticated account for sync mutations. Tests updated in the merge commit.

### F-10 Wide-open CORS
- Status: Resolved (`58db048`): origins must be listed in `ALLOWED_ORIGINS`.

### F-11 Large JSON bodies on every route
- Status: Resolved (`58db048`): 100 KB default; only `/api/community/media/upload` accepts 15 MB.

### F-12 Predictable user identifiers
- Status: Resolved (`58db048`): `crypto.randomUUID()`. Conversation identifiers use a hash when the joined identifier would not fit the 64-character column.

### F-13 Erasure requests recorded but not carried out
- Status: Resolved. Erasure now removes or anonymises the member's data and revokes tokens (`493e05d`, `e26abef`). The policy covers 61 person-linked columns, checked by `erasure_completeness.test.js`. Retained records are listed with their reasons in `ERASURE_POLICY`.

### F-14 Server boot could skip migrations
- Status: Resolved (`85985f3`). The server now runs the verified migration runner.

### F-15 Logging of raw error objects
- Status: Resolved for the community routes flagged by the logging scan (merge commit `040b723`). Remaining `console.error` calls log fixed messages.

### F-16 Classroom WebView JavaScript bridge
- Severity: Low (to be confirmed). Location: `ClassroomCallActivity.java:57-64`. The WebView disables file access, blocks mixed content and loads only the bundled `classroom.html`. The `ClassroomNative` bridge is exposed to that page.
- Status: Not verified in full. The bundled HTML and each bridge method were not reviewed.

### F-17 Gradle and npm dependency scan
- Status: npm (production dependencies): **0 vulnerabilities** on this branch (`npm audit --omit=dev`, run 2026-11-18). Gradle: not run (OWASP dependency-check not installed).

### F-18 Prebuilt native libraries have no recorded provenance
- Severity: Medium. Location: `src/main/jniLibs/arm64-v8a/libperazim_llama.so` (listed as pending in `NOTICE.md`).
- Impact: the origin of a shipped native library cannot be confirmed.
- Recommended fix: record the source revision and build hash, or remove the library.

### F-19 Release backend URL is a deployment secret
- Severity: Info. The release CI job needs `PERAZIM_RELEASE_API_BASE_URL`, which the owner sets in repository secrets. The build refuses a non-HTTPS value (`build.gradle`).

### F-20 Community and admin authorisation per route
- Status: Not verified in full. Verified: media access checks post, owner, chat and avatar scope (`community.js:46-66`); admin routes call `requireAdminAuthority` (`adminMembership.js:52-62`). Each other route in `community.js`, `membership.js` and `privacy.js` still needs a per-handler review.
