## Findings

### S-01 — Room database eligible for cloud backup and device transfer
- **Severity:** High (pending confirmation that the Room DB holds personal data)
- **Category:** MASVS-STORAGE
- **Location:** `src/main/AndroidManifest.xml:55` (`android:allowBackup="true"`); `src/main/res/xml/data_extraction_rules.xml` (excludes only `perazim_session_prefs.xml` and `perazim_session_token_v1.xml`).
- **Description:** Cloud backup and device-transfer rules exclude the session token files but not the Room database. Room is the offline store for user-linked data (for example prayers, messages and users; see the table list of the Room-backed schema).
- **Impact:** Personal data could leave the device through the user's Google backup or be copied during a device transfer.
- **Evidence:** the exclude list in `data_extraction_rules.xml` has two `sharedpref` entries and no `database` entry.
- **Recommended fix:** Add `<exclude domain="database" path="perazim_database.db" />` (and `perazim_database.db-wal`, `perazim_database.db-shm`) to both `cloud-backup` and `device-transfer`. The name is `DATABASE_NAME` in `PerazimDatabase.java:114`. Keep `allowBackup` only if the rules above are complete.
- **Notes:** The owner should confirm which Room tables hold personal data before severity is finalized. Table contents were not inspected in this pass.

### S-02 — Wide-open CORS
- **Severity:** High
- **Category:** OWASP API8 (security misconfiguration)
- **Location:** `server/src/index.js:21` (`app.use(cors());`)
- **Description:** CORS is enabled with no origin allow-list, so any website can call the API from a browser. The Android client does not need CORS.
- **Impact:** Any origin can read API responses for a logged-in browser session. Mitigated only if no cookie auth is used (bearer tokens only).
- **Recommended fix:** Replace with an env-driven allow-list, defaulting to deny (plan 3.5).

### S-03 — No HTTP hardening headers
- **Severity:** Medium
- **Category:** OWASP API8 / MASVS-N/A (server)
- **Location:** `server/src/index.js` (no `helmet`, no `app.disable('x-powered-by')`); `server/deploy/Caddyfile` (no `header` block).
- **Impact:** Responses leak `X-Powered-By: Express`; no HSTS, `X-Content-Type-Options`, `frame-ancestors` or `Referrer-Policy` at the edge.
- **Recommended fix:** `helmet` plus `app.disable('x-powered-by')` in the API; a `header` block in Caddy with HSTS, `nosniff`, `frame-ancestors 'none'` and `Referrer-Policy`.

### S-04 — Weak PIN policy and cost factor
- **Severity:** Medium
- **Category:** OWASP API2 (broken authentication)
- **Location:** `server/src/routes/auth.js:93-94` (minimum length 4); `server/src/routes/auth.js:103` (`bcrypt.hash(pin, 10)`).
- **Description:** A 4-digit PIN is accepted and hashed with bcrypt cost 10. The client already allows 12 digits.
- **Impact:** A 4-digit space (10,000 values) is trivially brute-forced if the hash leaks. Account lockout limits online guessing but not offline cracking.
- **Recommended fix:** Minimum 6 digits; bcrypt cost 12; enforce on both client and server.

### S-05 — Login rate limiter is in-memory
- **Severity:** Medium
- **Category:** OWASP API4 (unrestricted resource consumption)
- **Location:** `server/src/middleware/rateLimiter.js:9` (`const failedAttempts = new Map();`)
- **Description:** Failed-attempt counters live in process memory. They reset on every restart and are not shared between instances.
- **Impact:** Restarting the process (or a crash loop) clears lockouts. Credential stuffing is not throttled across restarts.
- **Recommended fix:** Store counters in PostgreSQL (or Redis) with a sliding window; add a global `express-rate-limit` (plan 3.5).

### S-06 — Enumeration of registered phone numbers
- **Severity:** Medium
- **Category:** OWASP API2 / business logic (plan item 20)
- **Location:** `server/src/routes/auth.js:100` (`409 'An account with this phone number already exists. Please log in.'`)
- **Description:** Registration reveals whether a phone number is registered. No OTP is required.
- **Impact:** Phone numbers of members can be confirmed by anyone who can reach the API.
- **Recommended fix:** Return a generic response for both new and existing numbers, or require a verification step before revealing existence.

### S-07 — Predictable user IDs
- **Severity:** Low
- **Category:** OWASP API1 (object references)
- **Location:** `server/src/routes/auth.js:104` (`'user_' + Date.now() + '_' + Math.random().toString(36).substring(2, 7)`)
- **Description:** IDs are built from a millisecond timestamp and a short non-cryptographic random suffix. They are guessable if registration time is known.
- **Recommended fix:** `crypto.randomUUID()` (plan 3.5).

### S-08 — 15 MB JSON body limit
- **Severity:** Medium
- **Category:** OWASP API4
- **Location:** `server/src/index.js:23` (`express.json({ limit: '15mb' })`)
- **Description:** Any JSON route accepts up to 15 MB, including base64 media. Each request holds that body in memory before validation.
- **Impact:** Memory exhaustion under concurrent large requests. The AI route is already limited to 4 KB (`server/src/routes/ai.js:26`), which shows the pattern works.
- **Recommended fix:** 100 KB default; multipart streaming with a size cap for uploads (plan 3.5).

### S-09 — Relay quota is a non-atomic read-then-write
- **Severity:** Medium
- **Category:** Race condition (plan item 11)
- **Location:** `relay/worker.js:215-245` (`PERAZIM_KV.get` then `PERAZIM_KV.put`).
- **Description:** Concurrent requests can read the same counter and both pass the cap. The code comment at line 8 and line 241 already states the quota is non-atomic.
- **Recommended fix:** Durable Object counter (plan 3.7).

### S-10 — Third-party GitHub Actions are pinned by tag, not SHA
- **Severity:** Low
- **Category:** Supply chain
- **Location:** `.github/workflows/*.yml` (six `uses:` lines, for example `actions/checkout@v4` and `android-actions/setup-android@v3`).
- **Recommended fix:** Pin each action to a full commit SHA, and enable Dependabot for the `github-actions` ecosystem.

### S-11 — No container HEALTHCHECK or explicit port hardening in the image
- **Severity:** Info
- **Location:** `server/Dockerfile`. Runs as `USER node` (positive). `server/deploy/compose.yml` uses an internal network with no host ports for the API (positive). `server/docker-compose.yml:26` binds `127.0.0.1:3000` (positive).
- **Recommended fix:** Add `HEALTHCHECK` in the image (plan 3.2).

## Controls verified as correct (positive evidence)

- **Media access is object-scoped.** `server/src/routes/community.js:46-66` checks post access, the owner, chat participants and the directory avatar before `sendFile`. Responses use `Cache-Control: private, no-store`. The filename regex blocks traversal.
- **In-memory SQL store fails closed in production.** `server/src/db.js:91-98` throws unless `ALLOW_MEMORY_STORE=true` and `NODE_ENV` is not `production`.
- **Production JWT secret is enforced.** `server/src/middleware/auth.js:6-21` and `server/src/index.js:69-78` refuse to boot without a 32-character secret outside development.
- **Classroom WebView is locked down.** `ClassroomCallActivity.java:59-61` disables file and content access and blocks mixed content. `shouldOverrideUrlLoading` returns `true`, and only the bundled `classroom.html` is served (`shouldInterceptRequest`).
- **Only the launcher activity is exported.** `AndroidManifest.xml:62` is `MainActivity`; every other activity is `exported="false"`.
- **Release minification is on.** `build.gradle` `release { minifyEnabled true; shrinkResources true }`.
- **Session token files are excluded from backup and transfer** (`data_extraction_rules.xml`).
- **Production DB is not published.** `server/deploy/compose.yml` has no host ports for the API or the database.
- **Dependencies (production, server).** `npm audit --omit=dev` reported 0 vulnerabilities across 99 production packages on 2026-11-18.
- **Service-grant verification.** `relay/worker.js:355-367` checks `alg` and `typ` before verifying the HS256 grant.
- **Admin authority is checked server-side.** `server/src/routes/adminMembership.js:52-62` calls `requireAdminAuthority` before each admin capability.
