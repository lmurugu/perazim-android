compiler exports from Room 2.6.1, not hand-written approximations:

The v4 and v5 JSON were regenerated by compiling temporary archives of those
exact Git commits with `exportSchema = true` and
`room.schemaLocation=$projectDir/schemas`. Version 6 was exported from the
current database declaration. The historical archives and generated build
outputs were kept outside the repository and removed after export. No user
backup or private device database was copied into fixtures. See
[`schemas/org.perazimchurch.app.data.local.PerazimDatabase/`](../../schemas/org.perazimchurch.app.data.local.PerazimDatabase/).

## Instrumentation coverage

The Android instrumentation suite is in
[`PerazimDatabaseMigrationTest.java`](../../src/androidTest/java/org/perazimchurch/app/data/local/PerazimDatabaseMigrationTest.java).
Its four migration cases use Room's `MigrationTestHelper` with the exported
schemas and synthetic rows:

- v4 → v5 validates the complete v5 exported schema and preserves synthetic
  user gamification values, a Bible note/favorite, and a pending sync payload.
- v5 → v6 validates the complete v6 schema and preserves the same kinds of
  rows; the new message `mediaUrl` column receives its migration default.
- v4 → v6 validates both migrations in sequence and the complete v6 schema.
- The tracked bundled v5 asset is copied to a unique `.validation` database
  name, then opened with Room v6. Its five translation verse counts remain
  unchanged (KJV/NIV/NKJV/SUV: 31,102 each; ESV: 31,103). A synthetic note,
  favorite, user, message, sync draft, and separate gamification preferences
  are checked. The bundled asset starts with zero users. The tracked asset is
  read only.

A fifth test was added to exercise a synthetic v6 SQLite file copy after Room
close and WAL checkpoint, then reopen the copy through Room schema validation.
It also verifies sample user, note, favorite, message, and queued draft rows and
checks that separate `SharedPreferences` balances remain separate from the
SQLite file. The final suite ran on the Infinix X689C running Android 11:
5 tests, 0 failures, 0 errors, 0 skipped, 5.207 seconds. The JUnit results are
in `docs/foundation/results/room-migrations.xml`.

The successful run used the isolated `.validation` target package and test
package; it did not install or clear the main application package. One retry
failed before device execution when the phone disconnected; after it was
reconnected, all five tests passed. A temporary x86 emulator attempt was
stopped before boot because the emulator required 7.37 GB free for its default
data partition while `/tmp` had 3.6 GB. It did not create or touch a user
database. An exploratory Robolectric run was stopped during its Android SDK
artifact download and is not counted as test evidence.

The final instrumentation output is preserved at
[`results/room-migrations.xml`](results/room-migrations.xml). The repository's
Android unit suite also passed: `testDebugUnitTest assembleDebug --offline
--no-daemon` completed successfully with 64 tests, 0 failures, 0 errors, and 0
skipped across 11 XML suites. The debug APK was assembled but not installed.
`git diff --check` passed.

## Data handling and support boundary

Fixtures contain synthetic rows only. The asset migration test reads the
tracked asset and works on a copy in the isolated validation app. No local
member database was opened, backed up, migrated, overwritten, or added to Git.

Room database version remains 6. Migrations 4→5 and 5→6 are unchanged. The
existing destructive fallback remains in place because the installed-version
fleet is unknown and source history does not prove support for versions 1–3 or
other unverified paths. Source history includes v3, but there is no established
migration path from v3 in the current builder. This evidence proves the listed
v4/v5/v6 cases and bundled asset case only; it does not establish safe upgrades
for every existing installation or complete an application backup/restore
workflow.
